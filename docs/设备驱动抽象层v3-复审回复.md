## 4. 对 v3 主文档的复审意见（主审部分）

**M1（更正）** §8-5 / §10.3 行 1/10 / §10.4 待办 1/7 基于 main 事实，按 §1 更正。
**M2（更正）** §10.3 行 8 计数（见上）。
**M3（复用修正）** §4.2「Mutex 当前唯一使用者是文件系统」是 **Xtask 本地事实**。本仓
`sync::Mutex` 使用面：`thread_local/boot/time/panic_support/log/hal/spi/sys/mbedtls` 等
10+ 文件。复用时该规则应表述为「**Mutex 不进设备驱动**」，而不是限定使用者清单。
**M4（未验证项）** §4.5 对 `sync::free` 的语义断言（关中断→抢全局自旋→每核深度计数、可重入）
是 **Xtask 实现**。本仓对应物 `sys::critical_section` 走厂商 `os_cs_enter/restore`
（`sys/mod.rs:1440`，三个后端各 4 行）——**可重入性与 SMP 行为未经厂商核**；host mock 是
不可重入进程锁（`pal/mock.rs:995`）。R1（区内方法 lock-free）可采纳，但 §4.5 的实现语义
对本仓应标"未验证"。
**M5（待定项落地路径）** §4.7 R3「厂商 API 只能在 owner 线程」——本仓 163 个契约方法现状
是调用方直调。R3 括号已允许「约定的唯一调用者任务」，接受此路径；但机器可判需要一张
**设备 → owner 任务**对照表。建议与 §10 第 10 项（`MODEL`/`CLAIMS` 待定）合并成一个
待定项：**设备归属表**（谁 owner、独占哪些资源）。
**M6（映射补正）** 见 D6。
**M7（符号名）** §10.3 行 11 的槽池符号是 `BlockId`（`device/event.rs`），表述采纳。
**M8（确认无误的部分）** §4 并发模型（原子性三来源、C0/C1/C2、R1–R7）与本仓既有纪律一致
（`debug_assert_not_isr!` 宏、"Mutex 禁止进 ISR"（`device/board.rs`）、scan 回调只拷值）；
§5.12/§5.13 对齐修订保留完整；§8.1 删除清单与 v1 顶部横幅处置无信息丢失（已核）。
