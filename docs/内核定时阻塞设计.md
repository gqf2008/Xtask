# 内核「限时阻塞」设计（v1 草案）

> 起因：`docs/设备驱动抽象层v3.md` §10 第 11 项「`recv_timeout` 在该内核上能否真阻塞」。
> 现状是 `sleep_ms` 分片轮询（`src/device/event.rs` 的 `recv_timeout` 每次睡 1 tick 再复查），
> 精度被节拍锁死、tickless 下每毫秒醒一次调度器，而且 `TransactionOp`、owner/actor 超时、
> `RegMap::poll_bits` 全都要跟着轮询。
>
> 本文只定**内核层**的形状。它顺带覆盖第 11 项以外的东西：任何「等一个信号，最多等 N tick」
> 的语义，在内核里都应该只有一条实现路径。

## 1. 现状：为什么现在做不到「真阻塞」

| 事实 | 位置 | 后果 |
|---|---|---|
| 任务只有四态 `Ready/Running/Suspended/Blocked/Terminated` | `src/task.rs:114` | 没有「等待对象 + 截止期」的复合态位 |
| `Task::wait(ticks)`：写 `wake_tick` + 置 `Blocked` | `src/task.rs:352` | 这是**睡眠**语义，无人能提前叫醒 |
| `Task::wakeup()`：`if state == Suspended { Ready + 入就绪队 }` | `src/task.rs:265` | 对 `Blocked` 的任务**完全无视**——信号到达等于丢了 |
| `submit_task` 的 `Blocked` 臂：`push_delay(task)` | `src/task/scheduler/xtask.rs:224` | 直接把 `Blocked` 等同于「在延时队列里睡觉」 |
| `DELAY`：按 `wake_tick` 升序的 `VecDeque`，tick 侧从队首摘到期段 | `src/task/scheduler/xtask.rs:41,407` | 出队即唤醒，没有「到点了但对象还没给结果」这个中间态 |
| `Task::bind()`：先 `retain` 摘旧队列再入新队列 | `src/task.rs:314` | **已有的好底子**：从 `DELAY` 提前搬到就绪队列是免费操作 |
| tickless 的最近期限 = `DELAY.front().wake_tick` | `src/task/scheduler/xtask.rs:445`、`idle.rs:112` | 只要限时等待挂在 `DELAY` 上，冻结/武装的期限计算**自动**正确 |

结论：不是缺一个大机制，而是缺**两个标志位 + 一条唤醒路径**。`DELAY` 的有序插入、
`bind` 的换队、tickless 的期限推导、`sync::free` 的临界区纪律，全都可以原样复用。

## 2. 目标 / 非目标

**目标**
1. `wait(对象, 截止期)` 一次睡到截止期，不在中间 tick 醒来；信号先到则**立刻**返回成功。
2. 超时与信号同时发生时只有一个赢家，且**已经到达的数据不丢**（例如事件已在环里，超时方宁可输）。
3. 共享代码：`EventChannel::recv_timeout`、`Semaphore::wait_timeout`、`TransactionOp` 的超时用同一原语。
4. tickless 下 `poll(fd)` 式等待不再按 tick 空转。

**非目标（明确不做，避免顺手造空壳）**
- 不加新的 `State` 变体（四态是调度器/SMP 判据的基础，扩展状态是连带灾难）。
- 不改 `sleep_ms`/`delay_us` 的语义与精度。
- 不做 `Mutex::lock_timeout`：超时后必须回退优先级继承，属独立的 PI 课题，本文不涉及。
- 不引入 `dyn WaitObject` 回调表；对象侧只提供**一个 `AtomicUsize` 等待槽**（见 §4.3）。
- 不做「一次等多个对象」（select/epoll 语义）。

## 3. 模型

**限时等待 = `Blocked` + `wake_tick`（截止期）+ `timed_wait` 标志 + `wait_result` 结果槽 + 等待槽回指**

- `wake_tick` 复用：它已经是 `DELAY` 的排序键，睡眠和限时等待共用同一根时间轴。
- `timed_wait: bool`：区分「睡着了」和「在等一个可能被提前给到的结果」。
- `wait_result`：`Signaled / TimedOut / Cancelled`，由**赢家**写入，输家不写。
- `wait_slot: *mut AtomicUsize`：对象侧等待槽的地址。tick 侧超时要能**撤销登记**，
  而 tick 侧拿不到对象——回指一个槽地址即可，语义与既有的 `blocked_lock`
  （PI 的锁回指，`src/task.rs`）同款。

新增字段（`src/task.rs`，`Task` 本身是堆对象，+2+8 字节）：

```rust
pub(crate) wake_tick: u64,        // 既有：DELAY 排序键
pub(crate) timed_wait: bool,      // 新增
pub(crate) wait_slot: *mut AtomicUsize, // 新增：0 = 已清
pub(crate) wait_result: WaitResult,     // 新增
```

**两种 `Blocked` 的判据**：`state == Blocked && timed_wait` = 限时等待；
`state == Blocked && !timed_wait` = 纯睡眠。所有既有代码只看前者是否成立，
所以对睡眠路径零影响。

## 4. 三条路径与裁决

### 4.1 进入等待（任务侧，一个 `sync::free` 内完成）

```rust
// 对象侧提供的复查闭包 + 等待槽地址
sync::free(|_| {
    if let Some(v) = try_take() { return Ready(v); }   // 复查：无事件才睡
    self.wait_slot = slot;                              // 登记回指
    self.wait_result = WaitResult::Pending;
    self.timed_wait = true;
    self.wake_tick = tick() + ticks;                    // 共用 DELAY 排序键
    self.state = State::Blocked;
    submit_task(self);                                  // Blocked 臂 → push_delay（有序插入）
});
yield_now();
```

「复查条件 + 登记 + 挂起」必须同一临界区：ISR 不能插进「发现空」与「挂起」之间——
这条纪律与 `EventDevice::register_waiter` 现有注释（`src/bsp/longan_nano/drv_uart.rs:254`）
完全一致，只是登记对象从裸任务指针换成带截止期的等待。

### 4.2 信号先到（调用方 = 任务 / ISR，任意上下文）

`wakeup()` 增加一条臂：

```rust
if state == Suspended {            // 既有：无声等待
    ...既有逻辑...
} else if state == Blocked && timed_wait {
    wait_result = Signaled;        // 赢家先写结果
    timed_wait = false;
    submit_task(task);             // Ready 臂 → push_ready → bind() 顺手把 DELAY 里的自己摘掉
}
```

`bind()` 的 `retain` 去重（`src/task.rs:314`）让「从延时队列提前搬到就绪队列」
成为一次普通入队——这是本设计能只改两个函数的关键。

### 4.3 超时先到（tick ISR）

`do_systick` 的 `take_expired` 回调里先做一次裁决再生效：

```rust
fn expire_task(task: *mut Task) {
    if timed_wait {
        // 谁先清等待槽谁赢：与对象侧 post 的 CAS 竞争，只有一个成功
        if !wait_slot.is_null()
            && (*wait_slot).compare_exchange(task as usize, 0, SeqCst, SeqCst).is_ok()
        {
            wait_result = TimedOut;
            timed_wait = false;
        } else {
            // 槽已被 post/唤醒方清掉 = 它先赢，本次到期作废（事件不丢）
            return;
        }
    }
    submit_task(task);
}
```

**「已经到达的数据不丢」由这个 CAS 保证**：`post` 先清槽 → 事件在环里、任务被唤醒；
tick 后到只能放弃。反过来 tick 先清槽 → `post` 的 CAS 失败，事件留在环里等下一次
`recv`，任务按 `Timeout` 返回。两种顺序都不会丢事件，也不会漏唤醒。

### 4.4 close / 取消

与 4.2 同一条臂，只是 `wait_result = Cancelled`。语义上「关闭通道」就是一次不成功的
信号，不需要第三条路径。

## 5. 对外的 API 形状

内核侧（`src/task.rs`，`pub(crate)`，不对外暴露状态机细节）：

```rust
pub(crate) enum WaitOutcome { Signaled, TimedOut, Cancelled }

/// 在给定等待槽上等待；调用者必须已在同一临界区内复查过条件。
/// `None` = 无限期（走既有 Suspended 路径，行为不变）。
pub(crate) fn wait_on_slot(slot: *mut AtomicUsize, deadline_ticks: Option<u64>) -> WaitOutcome;
```

上层只用它，不自己拼状态：

| 消费者 | 形态 | 本轮落地 |
|---|---|---|
| `EventChannel::recv_timeout` | 通道内单等待者槽 | Phase A ✅ |
| `Semaphore::wait_timeout` / `Queue::recv_timeout` | 复用同一 `wait_on_slot` | Phase B |
| `TransactionOp` / owner-actor 请求-应答 | 会话对象里的等待槽 | Phase B |
| `RegMap::poll_bits` | `sleep_ms` 分片 → 单次限时等待 | Phase B |

`recv_timeout` 改完后：一次 `wait_on_slot`，不再 `loop { try_recv; sleep_ms(1) }`；
精度 = 1 tick（与别处一致），但**中途不醒**。

## 6. tickless / SMP / 抢占的交互

- **tickless**：限时等待任务挂在 `DELAY` 上，`delay_next()`（`xtask.rs:445`）照旧给出准确期限，
  idle 引擎的「睡到最近期限」不变；`recv_timeout(50ms)` 从「50 次醒」变成「1 次睡 50ms」。
  `tickless_leave_idle` 的补账逻辑（`xtask.rs:60` 注释）不受影响——它只关心 `TICKS` 与节拍定时器的差。
- **SMP**：全部状态迁移都在 `sync::free` 内（关本核中断 + 全局自旋），裁决靠对象等待槽的
  `compare_exchange`，与 `src/device/event.rs` 的 `WaiterGuard` 同构。不需要新锁，
  也不引入「跨核写别人的 `Task` 字段」的新窗口——写操作都发生在持有 `free` 的一方。
- **抢占**：`submit_task` 的 `Ready` 臂已经会 `request_preempt_if_higher`；
  高优先级任务被信号唤醒仍在同一拍内抢占（`xtask.rs:210` 注释那处修复直接复用）。

## 7. 落地顺序与验收

**Phase A（内核原语 + `EventChannel`）**
1. `Task` 加三个字段 + `wakeup()` 新臂 + `expire_task` 裁决（`src/task.rs`、`xtask.rs`）。
2. `wait_on_slot` 原语。
3. `EventChannel::recv_timeout` 换实现，删掉分片循环。
4. 验收：
   - host 单测（`xtask.rs` 已有 `blocked_task` 夹具）：`expire_task` 在「槽已清 / 槽未清」两种
     情况下分别走 TimedOut 与放弃；`bind` 从 DELAY 提前搬运后 `DELAY` 里没有残留。
   - QEMU 执行级新增三项：① 信号在 5 tick 内到达 → 返回 `Signaled` 且耗时 < 20 tick；
     ② 无信号 → `Timeout`，随后 `post` 的事件仍能被下一次 `recv` 取到（不丢证据）；
     ③ `close` 打断限时等待 → `Cancelled`。
   - tickless：`recv_timeout(20 ticks)` 期间节拍唤醒计数 = 1（现实现 = 20）。

**Phase B（推广）**：`Semaphore::wait_timeout` / `Queue::recv_timeout` / `poll_bits`；
每推广一处删一处轮询循环，验收同 Phase A 的三条。

## 8. 风险与回退

| 风险 | 处置 |
|---|---|
| `timed_wait` 与既有 `Blocked` 语义混淆，导致睡眠任务被误当限时等待 | 判据写死两字段合取；`wait(ticks)` 显式置 `timed_wait = false` |
| 超时后对象侧未清槽 → 下一位等待者被幽灵唤醒 | 唯一登记点 + 唯一清槽点；`WaiterGuard::drop` 兜底 CAS |
| SMP 双核同时到期与 post | CAS 裁决 + `free` 内串行；QEMU `qemu_smp` 加一条双核限时等待用例 |
| `wait_slot` 野指针（任务被 `Terminated` 后 tick 仍持有） | 与 `blocked_lock` 同款纪律：只在 `Blocked && timed_wait` 期间有效，`Terminated` 前必被清 |
| 退不回去 | 改动集中在 `wakeup` 的一条 `else if` + `do_systick` 的到期回调；`recv_timeout` 保留旧实现对拍一个 release 周期 |
