## 0. 一页摘要

v3 的 §0–§9 是**通用规范**（面向所有嵌入式场景，不依赖任何具体项目）：能力写成类型化
trait；执行模型写进契约；原子性只由关中断、自旋锁、硬件原子指令提供；长操作由单 owner
actor 的所有权串行化，驱动内部零锁；业务结果与传输错误分开。

本说明的用途：把规范条款落到样本项目，逐条给出**已满足 / 需改动 / 规范缺口**三类结论。

原则：**规范先行，移植方适配规范**。样本项目可以用来暴露规范缺口，但不能反过来决定契约
形状；真要改规范，走 v3 修订并附最小反例，不在实现里开特例。

## 1. 范围

- **规范**：v3 §0–§9（通用，适用于任何嵌入式项目）。
- **项目记录**：v3 §10（非规范，记录样本项目的适配结果）。
- **本轮输出**：每条规范条款在样本项目上的对齐状态；规范缺口单独列出。

**不要求**：本轮不改业务代码、不改 PAL、不加驱动；规范也不因样本现状而放宽。

## 4. 六个对齐点

### D1 专用设备只实现 `DeviceBase` + 能力 trait

- **规范要求**：专用设备实现 `DeviceBase`（`kind()`）+ 对应能力 trait；**不实现** `Device`
  （不要求 `Sync`、不进 `as_*`、不进注册表）。
- **样本现状**：12 个设备句柄不实现任何 trait，直接提供方法。
- **需完成的改动**：12 个 `impl DeviceBase` + 12 个能力 impl；公共方法签名不变。
- **不改的后果**：无法按规范的能力契约调用；`kind()` 缺失。

### D2 独占设备的类型表达

- **规范要求**：独占设备必须用类型显式表达不共享（`Send + !Sync` 或等价证明），并配
  `compile_fail` 用例；不得用“调用约定”代替类型。
- **样本现状**：`feat/spk6-bsp @ 34fcfb6d` 已做到 13 句柄 `NotSync` + 13 `compile_fail`
  + `docs/device-exclusivity.md` 全矩阵。
- **需完成的改动**：无（作为参考实现记录，不作为规范依据）。
- **不改的后果**：类型上允许跨线程共享独占句柄，是一类可被编译器挡住的 bug。

### D3 超时语义

- **规范要求**：所有可能长时间等待的操作必须显式 `Duration`；**超时 ≠ 取消**——超时只保证
  调用方返回，不保证底层操作中止；trait 文档必须写明。
- **样本现状**：多数厂商阻塞调用没有超时参数。
- **需完成的改动**：在 owner/actor 边界实现超时；文档补“超时 ≠ 取消”。
- **不改的后果**：调用方无法给业务设置上界；UI/交易流程可能永久挂住。

### D4 `&self` 接收者

- **规范要求**：所有能力方法一律 `&self`；独占性由句柄所有权 + `!Sync` 表达。
- **样本现状**：`Pinpad::events(&mut self)`（`pinpad.rs:786`）是全库唯一的 `&mut self`。
- **需完成的改动**：改 `&self`；通道在 `start_pin` 时创建（优于 `RefCell` 的逐事件借用）。
- **不改的后果**：与“能力方法 `&self`”的规范冲突，同一能力出现两套签名。

### D5 事件订阅语义

- **规范要求**：默认**单订阅**（第二次 `events()` → `Err(Busy)`）；多消费者设备在 trait 文档
  显式声明并返回广播通道。
- **样本现状**：`Receiver<T>` 不可克隆（仅 `Sender: Clone`，`mpsc.rs:330`），本就是单消费者。
- **需完成的改动**：把默认语义写进 trait 文档；需要多消费者的设备单独声明。
- **不改的后果**：语义靠猜，换后端时行为不一致。

### D6 错误映射

- **规范要求**：端口必须提供 `DeviceError → 平台错误` 的映射，且不得丢失
  `Vendor{module,code}` 的原始码；映射表属于端口文档。
- **样本现状**：`crate::Error { ErrorKind, raw }`（20 个 kind，**无 `Io`**）。
- **需完成的改动**：写 `impl From<DeviceError> for Error`（示例见 v3 §10.5；`Io` 取 `Other`）。
- **不改的后果**：设备错误无法汇入统一错误类型，或厂商码在转换中丢失。

## 5. 验收口径

**规范侧（必须全部成立）**：能力方法 `&self`；独占设备 `!Sync` + `compile_fail`；错误映射
不丢厂商码；可能阻塞的操作有显式超时；事件默认单订阅。

**样本侧改动量（可数）**：公共方法签名 **1 处**（D4）；新增 12 个 `kind()` + 12 个能力 impl
+ 1 个 `From` + 1 个 `EventChannel` 别名；PAL 关联类型、四后端、事件槽池、错误分段不动。

## 6. 边界

- **规范不因样本改**：样本与 §0–§9 冲突时，改实现。
- **规范缺口**：若某条款确实无法实现，先提 v3 修订（附最小反例与影响面），不在实现里特判。
- 本轮不改业务代码、不改 PAL、不新增驱动。
